# 注释、API 契约与文档

## 代码注释

- **[强制]** 类、对外属性和类方法使用合法 Javadoc，而不是普通块注释。抽象/接口方法说明用途、参数、返回值和可能的异常。
- **[强制]** 类文档保留项目约定的作者和时间信息。若项目通过 Git 维护责任和历史，遵循项目约定，不新增易过时的作者标签。
- **[强制]** 方法内单行注释放在目标语句上方，`//` 后留一个空格；多行说明使用 `/* ... */`。每个枚举值说明业务含义。
- **[推荐]** 注释说明业务意图、设计决策、边界和非显然原因，不重述代码。用能准确表达的语言写作，专有名词和关键字保留英文。
- **[推荐]** 修改代码时同步更新参数、返回值、异常和核心逻辑注释。删除无用字段、方法、参数和内部类，不长期保留被注释掉的旧代码。
- **[参考]** `TODO/FIXME` 等特殊标记包含可追踪的责任人或任务标识及时间，并进入清理流程。

## API 契约

- **[强制]** API 文档明确协议、域名/服务、路径、HTTP 方法、请求头、请求体、状态码、响应结构和错误契约。字段名称与类型必须与实现一致。
- **[强制]** 列表无数据时返回空数组/空集合，不用 `null` 表示空列表。错误响应包含合适的 HTTP 状态码、稳定的 `errorCode`、便于排查的 `errorMessage` 和面向用户的安全提示（若需）。
- **[强制]** JSON 字段使用小写字母开头的 `lowerCamelCase`。超出 JavaScript 安全整数范围的 ID/整数以字符串传输。
- **[强制]** 限制 URL、请求体、批量数量、分页大小和上传文件的上限。手册的 2048 字节 URL 可作为保守基线，实际上限以客户端、网关和服务器配置中的最小值为准。
- **[强制]** 分页参数在契约中明确起始值、边界和越界行为。内部转发和外部重定向明确区分，外部目标经过受控的白名单/代理机制。
- **[推荐]** 响应明确缓存策略，默认使用 JSON。时间契约显式声明时区；新 API 优先使用 ISO 8601/RFC 3339 带偏移格式，已有系统则保持一致。
- **[参考]** API 版本可通过请求头、媒体类型或路径管理。手册倾向不在路径放版本，但应优先采用当前平台已确定的统一策略。

## 编写技术文档

- 以读者和决策为中心，区分需求、现状、约束、方案、取舍、风险、迁移/回滚和验证。
- 接口文档为请求/响应字段说明必填性、类型、范围、单位、枚举值、默认值、脱敏规则和错误场景。
- 文档与代码共同维护，不把“代码可读”当作省略模块依赖、业务场景、调用链、数据和非功能要求的理由。
