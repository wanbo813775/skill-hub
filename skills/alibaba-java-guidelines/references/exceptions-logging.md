# 错误码、异常与日志

## 错误码

- **[强制]** 错误码的目标是快速溯源和统一沟通。在已有系统中复用统一错误码平台，不在局部随意创建新编码。
- **[强制]** 手册基线为 5 位字符串：1 位错误来源 + 4 位数字编号，成功码为 `00000`；不在错误码中嵌入版本、严重级别或组织架构。若项目已有另一套稳定契约，应保持兼容而不强行替换。
- **[强制]** 错误码不直接当作给最终用户的提示。稳定编码、内部排障消息和用户可理解提示分离，不泄露内部实现。
- **[推荐]** 调用第三方失败时，将对方错误转换为本系统错误码，同时在受控日志/链路中保留原始编码以便定位。

## 异常处理

- **[强制]** 能通过入参、边界或状态检查防止的运行时异常，优先预检。不把抛出/捕获异常当作正常流程控制。
- **[强制]** `try` 块只包含真正可能失败的代码，按可恢复策略区分异常类型。捕获异常后必须处理、转换或继续抛出，不吞掉异常。
- **[强制]** 事务中捕获异常后如果仍需回滚，必须继续抛出或显式标记回滚。注意 Spring 默认仅对特定异常类型回滚。
- **[强制]** 资源必须可靠关闭。现代 Java 优先 `try-with-resources`；必须手工释放时放入 `finally`。`finally` 中不使用 `return`。
- **[强制]** 捕获类型必须覆盖实际抛出类型，不用不相关异常伪装错误。动态代理、RPC 或类加载边界只在确有链接错误风险时考虑 `Throwable`；普通业务代码不要泛化捕获 `Throwable`。
- **[推荐]** 允许返回 `null` 时在契约中明确说明，调用方必须判断。集合类返回值通常优先空集合，但不擅自改变旧契约。
- **[推荐]** 针对自动拆箱、链式调用、并发结果、级联属性、数组/集合元素等 `NullPointerException` 高发点建立明确的空值语义。
- **[推荐]** 使用有业务语义的异常，不直接抛没有语境的 `RuntimeException`。对外 API 转换为稳定错误契约，应用内部保留可追踪异常链。

## 日志

- **[强制]** 业务代码依赖 SLF4J 等日志门面，不直接绑定 Logback/Log4j 实现 API。
- **[强制]** 日志留存期、安全事件记录和敏感操作审计必须符合现行法律与组织政策。手册对普通日志提出至少 15 天基线，但不把该数值代替当前合规要求。
- **[强制]** 日志使用占位符参数，不先做字符串拼接。高频 `trace/debug/info` 日志在构造昂贵参数前检查级别。
- **[强制]** 避免重复打印同一异常；根据日志框架正确配置传播/additivity。生产代码不用 `System.out/System.err` 或 `printStackTrace`。
- **[强制]** 异常日志同时包含足够的业务现场和异常链。不只打印 `exception.getMessage()`。不为打日志直接序列化整个对象，避免性能问题、循环引用和敏感数据泄露。
- **[推荐]** 生产不输出 debug 日志，info 只记录稳定的业务里程碑。用户输入错误可用 warn，系统或依赖故障根据影响使用 error。
- **[推荐]** 日志文案使用团队能准确检索和理解的统一语言；无论中英文，都保留稳定关键词和结构化字段。
