# MySQL 开发规约

在应用这些规则前确认 MySQL 版本、字符集、ORM、数据量级、一致性要求和团队 DDL 流程。手册的行数、容量和 SQL 数量阈值是经验基线，不代替实际测量。

## 建表

- **[强制]** 是/否字段使用 `is_xxx` 名称并定义明确的 0/1 语义，在 Java 属性中映射为无 `is` 前缀的布尔名。具体数据类型根据 MySQL 版本和项目标准选择。
- **[强制]** 表名和字段名仅使用小写字母、数字和单下划线分隔，不以数字开头，不使用 MySQL 保留字。表名使用单数。
- **[强制]** 索引名称使用 `pk_`/`uk_`/`idx_` 前缀并体现字段。精确小数使用 `decimal`，不使用 `float/double` 存储金额或精确数值。
- **[强制]** 长度几乎固定的短字符串可用 `char`；`varchar` 长度根据实际分布设置，超长文本分表或使用合适的 text/对象存储方案。
- **[强制]** 业务表至少具有主键、创建时间和更新时间；名称与类型遵循项目统一约定。
- **[推荐]** 表名体现“业务_作用”，库名与应用名关联。字段含义或状态扩展时同步更新注释。
- **[推荐]** 只在明确读性能收益、写入和一致性策略后增加冗余字段。分库分表基于增长、访问模式和实测，手册的 500 万行/2GB 只是开始评估的参考。
- 现代 MySQL 新系统通常使用 `utf8mb4` 而不是旧 `utf8`，并显式确定 collation。

## 索引

- **[强制]** 业务上唯一的单字段或组合字段建立唯一索引，用数据库约束守住数据完整性。
- **[强制]** 手册要求联表不超过 3 张；无论数量如何，关联列类型/字符集保持一致，被驱动列有可用索引。超过时必须用执行计划和压测证明合理性。
- **[强制]** 为超长 `varchar` 索引设置合理前缀长度，根据区分度验证。在普通 B-tree 索引上不使用左模糊/全模糊查询；需求明确时使用全文索引或搜索引擎。
- **[推荐]** 联合索引同时考虑等值条件、区分度、范围条件、排序和最左前缀，不仅按单一“区分度最高在最左”口号设计。
- **[推荐]** 用覆盖索引减少回表，深分页使用 seek/keyset 或延迟关联。使用 `EXPLAIN ANALYZE`/实测检查扫描行数、访问类型、回表、排序和临时表。
- **[推荐]** 谓词值与字段类型一致，防止隐式转换让索引失效。

## SQL

- **[强制]** 统计行数使用 `count(*)`；理解 `count(col)` 忽略 `NULL`、`sum` 可能返回 `NULL` 的语义。NULL 判断使用 `IS NULL/IS NOT NULL`（手册文中 `ISNULL()` 是 MySQL 特定函数，跨数据库 SQL 优先标准语法）。
- **[强制]** 分页统计为 0 时不再执行列表查询。手册要求不使用外键/级联和存储过程；这是架构取舍而非普遍真理，新系统应根据一致性、性能、迁移性和运维能力在评审中确定。
- **[强制]** 数据订正，尤其删除/更新，先用同条件 `SELECT` 确认范围，使用事务、备份/回滚方案和变更审计。
- **[强制]** 多表查询/更新为列加表别名，避免歧义和表结构演化导致的错误。
- **[推荐]** 表别名使用统一、可读风格。`IN` 列表设置上限，数量较大时改用批处理、临时表、join 或其他受控方案。
- **[参考]** `TRUNCATE` 与 `DELETE` 在事务、触发器、权限、自增值和日志上的语义不同，不仅因速度替换。

## ORM

- **[强制]** 查询显式列出需要字段，不使用 `SELECT *`。Java 布尔属性与数据库 `is_xxx` 在 `resultMap`/映射中显式对应。
- **[强制]** 显式定义查询结果映射，不因属性“当前恰好同名”依赖脆弱的自动映射。MyBatis 值参数使用 `#{}`；`${}` 只能用于经白名单选择的元数据，不接受用户输入。
- **[强制]** 查询结果使用有语义的 DTO/DO，不直接用 `HashMap/Hashtable` 作为对外结果契约。更新业务数据时同步更新 `update_time`。
- **[推荐]** 更新方法只接收允许修改的字段，不把大而全的 POJO 直接写回，防止误覆盖。事务范围要小且明确，注意 Spring 代理边界、异常回滚和长事务影响。
