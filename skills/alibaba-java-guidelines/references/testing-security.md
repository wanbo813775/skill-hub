# 单元测试与安全规约

## 单元测试

- **[强制]** 遵循 AIR：测试自动化（Automatic）、相互独立（Independent）、可重复执行（Repeatable）。不需要人工输入或核对输出，不依赖执行顺序、真实外部环境或不稳定时间。
- **[强制]** 单测粒度最大到类级，目标是快速定位失败。核心业务、核心应用和核心模块的增量代码必须通过相关单测。
- **[强制]** Maven/Gradle 标准 Java 工程中单测放在 `src/test/java`，不与生产代码混放。
- **[推荐]** 普通模块语句覆盖率以 70% 为手册基线，核心模块的语句和分支尽量全覆盖。覆盖率是缺口信号，不是用无意义断言填满的交付目标。
- **[推荐]** 遵循 BCDE：覆盖边界（Border）、正确输入（Correct）、设计契约（Design）和错误路径（Error）。
- **[推荐]** 数据库测试不假定数据已存在，自行准备并清理数据。使用事务回滚、专用容器/实例或确定性 fixture，不污染共享环境。
- **[推荐]** 对难以测试的代码改善设计与依赖边界，不为了便于 mock 而暴露不应公开的实现。在设计评审时确定核心测试范围，并在提测/发布前完成。

## 安全规约

这些条目是最低工程基线，不代替当前 OWASP 指南、组织安全政策、隐私规则或威胁建模。

- **[强制]** 属于特定用户/租户的页面、资源和操作必须在服务端执行对象级授权，不仅依赖页面按钮隐藏。
- **[强制]** 敏感数据在展示、日志、导出、缓存和错误信息中按最小必要原则脱敏。密码、令牌和密钥不输出。
- **[强制]** SQL 值使用参数绑定；表名、列名、排序字段等无法绑定的元数据只能从受控白名单选择，不拼接用户输入。
- **[强制]** 所有不可信输入按使用场景校验类型、长度、范围、格式、枚举值、文件类型和业务权限。校验后仍在目标上下文使用正确编码/转义。
- **[强制]** 输出到 HTML/JavaScript/CSS/URL 的数据按对应上下文编码，不把未过滤的用户数据直接写入页面。
- **[强制]** 浏览器会话中具有副作用的表单/AJAX 请求启用与当前认证架构相符的 CSRF 防护。无状态 Bearer Token API 不机械套用 Cookie 场景方案，但要防止令牌泄露和重放。
- **[强制]** 外部重定向只允许白名单目标或服务端映射的标识符，不直接信任完整 URL。
- **[强制]** 短信、邮件、电话、下单、支付等有成本或资产影响的操作实现幂等、防重放、频率限制和审计。
- **[推荐]** 用户生成内容实现防刷、频控、风控和与业务/法律相符的内容治理，并为误判保留申诉和审计路径。
